LocalGRC

Manual Técnico, Instalação e Troubleshooting

1. Requisitos de Hardware

  • CPU: 2 Cores (mínimo), 4 Cores (recomendado).
  • RAM: 4 GB (para correr o modelo de IA llama3.2:1b). Se quiseres usar modelos maiores (ex: llama3.1:8b), precisas de 8 GB ou mais.
  • Disco: 20 GB de espaço livre.
  • Software: Docker e Docker Compose instalados no servidor (Windows com WSL2, Linux ou macOS).

2. Instalação Passo-a-Passo

Executa estes comandos no terminal do servidor:

  1. Clona o repositório e entra na pasta: 
    git clone https://github.com/mareginter/localgrc.git
cd localgrc
  2. Cria o ficheiro de ambiente e configura os segredos: 
    cp .env.example .env
    Abre o .env e altera a POSTGRES_PASSWORD e a DJANGO_SECRET_KEY.
  3. Constrói e levanta os contentores: 
    docker compose up -d --build
  4. Inicializa a base de dados e cria o admin: 
    docker compose exec app python manage.py migrate
docker compose exec app python manage.py bootstrap
  5. Descarrega os modelos de IA: 
    docker compose exec ollama ollama pull llama3.2:1b
docker compose exec ollama ollama pull nomic-embed-text

3. Troubleshooting (Erros Comuns)

Erro 502 Bad Gateway no Browser

Sintoma: O browser mostra "502 Bad Gateway".

Causa: O Nginx não consegue falar com o Django (o contentor app falhou ou está em loop de reinício).

Solução:

  1. Vê os logs do Django: docker compose logs app --tail 50
  2. Se houver um Traceback (erro de Python), corrige o ficheiro e corre: 
    docker compose up -d --build app
  3. Se for apenas o Nginx com cache do IP antigo: 
    docker compose restart web
Erro 500 Internal Server Error

Sintoma: A página carrega mas mostra erro 500 (sem detalhes).

Causa: O Django crashou ao processar a view (ex: falta de tabela na base de dados ou Template em falta).

Solução:

  1. Muda DJANGO_DEBUG=true no ficheiro .env.
  2. Reinicia o Django: docker compose restart app.
  3. Abre a página no browser para ver o erro exato (ficará amarelo).
  4. Se for ProgrammingError: relation does not exist, aplica as migrações: 
    docker compose exec app python manage.py makemigrations
docker compose exec app python manage.py migrate
Erro de Permissão (Permission denied)

Sintoma: Uploads de PDFs falham ou a app não consegue gravar ficheiros.

Causa: O Docker criou as pastas do volume como root, mas o Django corre como utilizador app.

Solução: Corrige as permissões da pasta de uploads:

docker compose exec --user root app chown -R app:app /data/uploads
O Assistente AI diz que o modelo não está instalado

Sintoma: Na tab Assistant, aparece um aviso vermelho ou amarelo sobre o Ollama.

Solução: Descarrega o modelo manualmente: 

docker compose exec ollama ollama pull llama3.2:1b
docker compose exec ollama ollama pull nomic-embed-text

Nota: Se o modelo descarregar mas falhar com "Out of Memory", o teu servidor não tem RAM suficiente. Muda para o modelo qwen2.5:0.5b no ficheiro .env.

4. Restaurar Backups (Disaster Recovery)

Os backups automáticos são guardados na pasta /backups do servidor (fora do Docker). Se precisares de restaurar um desastre:

Restaurar a Base de Dados (PostgreSQL)

# O ficheiro .dump tem de estar na pasta backups/
docker compose exec -T db pg_restore -U localgrc -d localgrc < backups/db_YYYYMMDD_HHMMSS.dump

Restaurar os Ficheiros (PDFs e Evidências)

# Extrai o ficheiro tar.gz para dentro do volume de uploads
docker compose exec -T app tar -xzf /backups/uploads_YYYYMMDD_HHMMSS.tar.gz -C /data/uploads/
